## 这是什么

Kestrel 是一套给 AI 代理（agent）用的**渗透测试操作手册**。它不替代扫描器，也不自动生成报告——它把「测什么、为什么测、测到什么、证据在哪」这条线串起来，让 AI 代理在授权范围内做渗透测试时，有章可循、有据可查、可交接。

25 个技能模块（skill）是 markdown 写的操作指南。AI 代理启动时只看到每个模块的名字和用途，真正需要时才加载正文——不占上下文。

> **授权前提**：仅用于你拥有或已获得明确授权的目标。完整边界见[安全声明](#安全声明)。

> **运行环境**：**执行环境依赖 Kali Linux**——技能列表不是工具白名单。实际执行渗透测试依赖 Kali 的工具环境。缺工具时按 `apt → pipx → npm → go → gem → 二进制/JAR` 的顺序安装，安装记录写入 `notes.md`。

## 核心特点

| 特点 | 说明 |
|:---|:---|
| **证据驱动** | 工具输出只算线索；标「已确认」必须附原始响应和第二种独立信号，每个结论都能追溯到证据 |
| **可交接** | 所有记录（资产清单、测试项、回顾、清理记录）都落在 `Work/OC-<target>/` 目录——换人接手不用重来，压缩或重启都能续 |
| **授权可控** | 授权规则写进 `roe.yaml` 文件，按风险分四级；高风险操作逐次授权——边界是文件，不是模型记忆 |
| **按需加载** | 启动只加载 25 个技能模块的名称与用途；需要时才读正文，用不到的模块不占上下文 |
| **零依赖** | 25 个技能模块以 markdown 为主，附 4 个零依赖 Python 脚本，复制进技能目录即用——不装服务、不建库、不改环境 |
| **离线/在线知识库** | AI 组件漏洞库、注入算子库、Agent 检测清单与攻击链全部内置，断网也能查；联网时接 NVD / OSV（漏洞数据库）补最新数据 |

## 快速开始

```bash
git clone https://github.com/oc-liby/Kestrel.git
cd Kestrel
cp -a skills/. ~/.claude/skills/    # 换成你客户端的技能目录
```

在任意工作目录启动客户端，直接说目标：

```text
打 10.0.0.5，目标 RCE
```

AI 代理会建立 `Work/OC-10.0.0.5/` 目录，写授权规则，摸清资产，然后按清单推进逐步完成任务目标。

## 工作流程

```text
┌──────────────────────────────────────────────────────┐
│ ① 启动                                               │
│    目标 → 授权规则 → 加载技能模块 → 摸清资产         │
│    ⛔ 检查点：全端口扫描完成，每端口一行             │
└──────────────────────────────────────────────────────┘
                           │
                           ▼
┌──────────────────────────────────────────────────────┐
│ ② 测试循环                                           │
│    按资产清单逐项测试 → 记录 → 回顾                  │
│    ⛔ 检查点：待办项全部完成，才算测完               │
└──────────────────────────────────────────────────────┘
                           │
                 5 轮无新发现且全部测完
                           ▼
┌──────────────────────────────────────────────────────┐
│ ③ 结束检查 14 项 → 用户确认 → 交付发现报告           │
└──────────────────────────────────────────────────────┘
```

**四个强制检查点，缺一不得进入下一阶段**：

| 检查点 | 位置 | 判断标准 |
|:---|:---|:---|
| **技能加载** | 进入任何阶段前 | 工作记录里必须有「技能加载」表，缺行不得进入 |
| **摸清资产** | 发送任何攻击载荷前 | 全端口扫描完成、每端口一行、资产清单覆盖全部端口 |
| **测试项完整** | 标「已排除」前 | 该方向适用项全部「已完成」或「不适用」，受阻项写明已尝试 |
| **结束检查** | 宣布结束前 | 14 项全过 + 用户确认 |

**关键节点**：

- **拿到容器控制权后强制重画环境地图**（`env-map.md`）——从「从外面打进去」切换成「从里面打出去」的视角。外面的地图看不到容器内的网络、挂载、环境变量、凭据、云元数据；不重画就等于拿着旧地图打新战场，会漏掉内网和宿主机。
- **每轮回顾必须带具体对象**（资产清单行号 / 测试项 / 证据路径），空泛的「无新发现」不计入轮次。
- **结束前资产清单里「未测试」必须全部完成**，测试项清单无「待办」/「进行中」。

## 授权分级

按风险从低到高分四级，高风险操作需要逐次授权：

| 等级 | 范围 | 默认 |
|:---|:---|:---|
| **L0–L2** | 被动收集、端口 / 子域扫描、只读验证、默认口令、弱口令 ≤top100 | ✅ 直接做 |
| **L3** | 只新增自己的对象或可回滚的改动 | ✅ 直接做 |
| **L3-⚠️** | 大字典爆破、密码喷洒（不主动提出）、账户锁定测试、修改账号密码 | ⚠️ 逐次授权 |
| **L4** | 改变目标原有状态或不可逆 | 🔴 明确授权后执行 |

**L3 覆盖**：目录爆破、WAF 绕过、可清理写入、测试上传、网页后门（WebShell）、用户级/系统级持久化驻留、内存后门、systemd（Linux 服务管理器）、修改配置与回滚（有备份）、启停自己创建的服务、固定路径新建、同目标横向移动、数据导出、用户态权限提升、域控制器只读、自建 Pod/Job（K8s 工作负载）、只读 K8s 枚举。

**L4 覆盖**：无法回滚的修改、停止/重启目标原有服务、为生效而重载其配置、重启主机、清防火墙、拒绝服务（DoS）、删除数据、覆盖文件/证书/密钥、同名覆盖、格式化、勒索软件、清日志、内核权限提升、域控制器写入、横向移动到授权范围外、逃逸到 Node/宿主机、修改目标/集群级 RBAC（基于角色的访问控制）、etcd（K8s 数据库）、云控制面。

**判断标准**：动自己新增的对象 → L3；动目标原有对象看能否回滚——配置类可回滚 → L3，业务文件 / 证书 / 密钥 → L4；让改动生效所需的重载 / 重启目标服务 → L4；容器/K8s/云按宪法 §14。

完整分级见 `skills/pentest-flow/references/constitution.md`——它是授权规则的唯一来源。

## 生成的文件

```text
Work/OC-<target>/
  roe.yaml          # 授权规则
  plan.md           # 工作记录：资产清单、测试项、覆盖清单、假设、权限记录、回顾、结束检查
  attack-path.md    # 攻击路径：入口 → 最高控制权
  env-map.md        # 环境地图（拿到容器控制权后重画）
  findings.md       # 发现报告（交付物）
  approvals.md      # ⚠️ 高风险操作授权记录
  cleanup.md        # 清理记录
  notes.md
  evidence/
    scripts/        # AI 代理写的脚本
    src/            # 原始输出、源码、攻击载荷
    tokens/         # 凭据
```

不生成 `report.md`——`findings.md` 就是交付。

## 设计原则

**一条主线：把纪律写进文件，把判断留给 AI 代理。** 强制检查点只管「不能跳过什么」，不管「下一步做什么」——发现什么、先打哪、何时换路，由 AI 代理根据现场判断。

| 原则 | 一句话 | 实际体现 |
|:---|:---|:---|
| **技能是参考** | 不预加载，按信号加载 | 25 个技能模块，启动只读名称与用途；需要时才读正文 |
| **先摸清资产再攻击** | 先画完地图，再决定打哪 | 摸清资产检查点：全端口扫描 + 每端口一行 + 清单覆盖 |
| **线索不是结论** | 单一工具最多算「疑似」 | 「已确认」需原始响应 + 第二种独立信号或可复现回显 |
| **授权写进文件** | 不靠记忆，靠 `roe.yaml` | 四级分级 + 禁止边界，高风险逐次授权 |
| **产物自包含** | 不依赖服务 / 状态机 | `Work/OC-<target>/` 全量落盘，压缩或换人接手都能续 |
| **如实交付** | 打不下来不硬撑 | 卡住时按 §8.3 交付，不索要凭证、不把「需要爆破」当下一步 |

> **原则靠强制检查点落地，不靠模型记忆**：四道强制检查点写在 `references/` 里——技能加载、摸清资产、测试项完整、结束检查。授权边界由 `roe.yaml` + `constitution.md` 强制执行，产物完整性由结束检查逐项核对。

## 安全声明

Kestrel 仅用于**你拥有或已获得明确授权**的目标。未授权扫描、入侵、数据获取或破坏均可能违法，本项目不为此提供任何支持。

使用前必须：

- 确认授权范围、时间窗和排除资产，并写入 `roe.yaml`；
- 遵守授权分级表：L0–L3 直接做（其中 ⚠️ 项逐次授权），L4 经明确授权后执行（授权即执行，无二次确认）；
- 不把工具输出当作授权依据，不越过 `scope`、`exclude_assets`、`time_window`、`max_rate`。

测试产物可能包含凭据、token、业务数据和个人信息。`evidence/tokens/` 与 `findings.md` 应按敏感数据处理，仅保存在授权环境，结束后按约定清理或移交。
